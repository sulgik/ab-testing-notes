04 · 지표 설계: OEC, guardrail, sensitivity

Kohavi 6·7장에 해당 · 무엇을 재는가가 무엇을 최적화하는가를 정한다

진단 질문

  1. 검색 서비스의 성공 지표로 "세션당 검색 횟수"를 쓰면 무엇이 잘못될 수 있나?
  2. 좋은 실험 지표의 조건을 세 가지 들라.
  3. "매출"은 거의 모든 회사의 목표인데, 왜 실험의 1차 지표로는 잘 안 쓰나?
  4. OEC(Overall Evaluation Criterion)가 무엇이고, 왜 지표를 여러 개 두는 대신 하나로 합치려 하나?
  5. 지표가 "민감하다"는 말의 두 가지 뜻은?

1. 지표의 네 종류

종류역할예
goal metric (goal)조직이 궁극적으로 원하는 것. 느리게 움직이고 실험 하나로는 잘 안 움직인다장기 매출, 사용자 생애 가치, 시장 점유율
driver metric (driver)목표의 선행 지표. 실험 기간 안에 움직이고, 목표와 인과적으로 연결된다고 믿는 것재방문율, 세션당 성공 과업 수, 구독 전환
guardrail (guardrail)나빠지면 안 되는 것. 출시를 막는 조건지연시간, 오류율, 구독 해지, 그리고 SRM 같은 신뢰성 지표
debug metric (debug)왜 움직였는지 설명하는 세부 지표. 결정에는 쓰지 않는다퍼널 단계별 전환, 기능별 클릭
실험의 1차 지표는 보통 driver metric다. goal metric은 너무 느리고 잡음이 커서 2주 실험으로 움직이지 않는다. driver metric을 고른다는 것은 "이것이 오르면 장기 목표도 오른다"는 인과 가설을 세우는 일이고, 그 가설은 따로 검증해야 한다 (09회의 surrogate metric).

2. 좋은 지표의 조건

  • 방향이 명확하다. 오르면 좋은지 내리면 좋은지 논쟁이 없어야 한다. "세션당 검색 횟수"는 검색 품질이 나빠져도 오른다(원하는 걸 못 찾아 다시 검색). 방향이 모호한 지표다.
  • 조작하기 어렵다. 지표를 올리는 가장 쉬운 방법이 사용자에게 좋은 방법이어야 한다. 클릭 수는 미끼 제목으로 올릴 수 있다. 클릭 후 체류나 재방문은 그보다 어렵다.
  • 민감하다. 실험 규모에서 실제 변화를 잡아낼 수 있어야 한다. 아래 §4.
  • 실험 기간 안에 움직인다. 연간 해지율은 좋은 goal metric지만 2주 실험의 지표가 될 수 없다.
  • 이해하기 쉽다. 결정하는 사람이 지표의 뜻을 설명할 수 있어야 한다. 복잡한 가중합은 신뢰를 잃는다.

3. OEC: 하나로 합치는 이유와 위험

지표가 열 개면 어느 하나는 우연히 유의해지고, 팀은 좋은 것만 고른다. 그래서 사전에 key metric을 하나 또는 가중합 하나로 정한다. 이것이 OEC다.

  • OEC는 보통 driver metric 몇 개의 가중합이고, 가중치는 "장기 목표에 얼마나 기여하는가"에 대한 조직의 판단이다.
  • OEC가 오르더라도 guardrail이 깨지면 출시하지 않는다. OEC는 "이겼는가", guardrail은 "해를 끼쳤는가"를 묻는다.
  • 위험: 가중합 안에서 한 항이 다른 항의 하락을 가린다. 그래서 OEC와 함께 구성 항도 본다.

매출을 OEC로 잘 안 쓰는 이유는 셋이다. 꼬리가 길어 잡음이 크고(03회), 단기 매출은 장기 가치와 어긋날 수 있고(가격 인상은 단기 매출을 올린다), 많은 실험이 매출에 직접 닿지 않는다.

4. sensitivity: 두 가지 뜻

"민감한 지표"는 두 가지를 동시에 말한다.

  1. 통계적 power. 같은 표본에서 분산이 작아 작은 변화도 유의하게 나온다. 분산을 줄이는 방법: capping, 변환, 비율 대신 사용자당 지표, CUPED (01회).
  2. 움직일 가능성. 실험이 바꾸는 것과 지표 사이의 거리가 짧다. "세션당 과업 완료"는 UI 변경에 반응하지만 "월간 활성 사용자"는 거의 반응하지 않는다.

두 뜻은 충돌할 수 있다. 가장 민감한 지표(클릭)는 장기 목표와 가장 먼 지표이기도 하다. 그래서 실무는 "충분히 민감하면서 목표와 연결된" 지표를 찾는 일이고, 과거 실험 수백 개로 어떤 지표가 어떤 실험에 반응했는지를 되돌아보는 것(12회의 meta-analysis)이 그 근거가 된다.

5. 지표를 검증하는 법

  • 과거 실험으로 역검증. 출시 후 장기 결과가 좋았던 실험들에서 이 지표가 올랐었는가? 나빴던 실험에서 내렸었는가?
  • 의도적 열화 실험. 결과 페이지를 일부러 느리게 하거나 검색 결과 품질을 낮춰서, 지표가 "나빠짐"을 잡아내는지 본다. 지표가 반응하지 않으면 그 지표로는 개선도 잡을 수 없다.
  • A/A 테스트. 처치가 없을 때 지표가 유의하게 움직이는 비율이 5%를 넘으면 분산 계산이 틀린 것이다 (06회).

확인 문제

Q1. 뉴스 앱의 1차 지표 후보: 일일 활성 사용자, 기사당 체류 시간, 세션당 기사 수, 7일 재방문율. 각각의 약점을 한 줄씩.
Q2. 알림을 늘렸더니 세션 수는 +8%, 알림 끄기(opt-out)는 +30%다. OEC·guardrail 틀로 판단하면?
Q3. "지표가 민감하지 않다"는 말을 들었을 때 확인해야 할 두 가지는?
Q4. 지표를 일부러 나쁘게 만드는 실험을 왜 하나? 윤리적 한계는?
정답
  1. DAU: 느리고 잡음이 크며 실험 하나로 안 움직인다. 체류 시간: 방향이 모호하다(못 찾아서 오래 있을 수 있다). 세션당 기사 수: 미끼 제목으로 조작 가능. 7일 재방문: 좋은 동인 후보지만 실험 기간이 최소 2주 이상 필요하고 sensitivity가 낮다.
  2. 세션 수(동인)는 올랐지만 opt-out(guardrail)이 크게 나빠졌다. guardrail 위반이면 출시하지 않는다. opt-out은 장기 해지의 선행 지표이기도 하다.
  3. ① 분산이 큰가(통계적 power 문제 → CUPED, 절단, 사용자당 지표로 개선 가능한가) ② 실험이 바꾸는 것과 지표의 거리가 먼가(지표 선택 문제).
  4. 지표가 "나빠짐"을 잡아내는지 확인하려고. 잡아내지 못하는 지표는 개선도 못 잡는다. 한계: 사용자 피해가 작고 짧아야 하며, 되돌릴 수 있어야 한다 (12회의 윤리).
