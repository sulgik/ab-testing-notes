02 · 왜 실험하나, Twyman's Law, 성공률과 거짓 발견 비율

Kohavi 1·3·4장에 해당 · 2026-10-16

진단 질문

먼저 답해 보세요.

  1. 실험 없이 "출시 전후 비교"로 효과를 판단하면 무엇이 문제인가? 전후 비교보다 더 그럴듯해 보여서 더 위험한 비교 방법은?
  2. Twyman's Law를 한 문장으로. 실험 결과에 적용하면 어떤 행동 수칙이 되나?
  3. "아이디어의 몇 %가 실제로 지표를 개선하는가"는 대략 얼마인가? 그 숫자가 실험 문화에 주는 의미는?
  4. 실험 조직의 성숙도를 단계로 나눈다면 어떤 축으로 나누겠나?
  5. 작은 UI 변경에서 매출 +10%가 나왔다. 처음 10분 동안 무엇을 확인하겠나?

1. 실험이 아닌 비교가 틀리는 두 가지 방식

전후 비교. 출시 전 지표와 출시 후 지표를 비교하면 효과가 시간 효과(계절성, 추세, 같은 시기의 다른 변화)와 섞인다. 12월에 출시하고 "늘었다"고 하면 연말 효과인지 기능 효과인지 알 수 없다. 누구나 의심하는 방식이라 그나마 덜 위험하다.

사용자 간 비교 (자기선택). "새 기능을 쓴 사용자 vs 안 쓴 사용자"를 비교하는 것. 기능을 쓴 사람은 애초에 더 활동적이거나 다른 사람이다. 효과가 아니라 누가 쓰는가를 재는 것인데, 그럴듯해 보여서 더 위험하다.

대표 사례: "오류를 본 사용자의 이탈률이 더 낮다." 오류를 볼 만큼 많이 쓰는 사람이라서 그렇다. 오류를 늘리면 안 된다.

무작위 배정은 이 둘을 한 번에 해결한다. 같은 시기를 겪는 대조군이 있고(시간 효과 제거), 누가 처치를 받을지 사용자가 아니라 동전이 정한다(자기선택 제거).

2. Twyman's Law

흥미롭거나 특이해 보이는 숫자는 대개 틀렸다.

사회조사 통계학자 Tony Twyman의 경험칙이고, Kohavi는 이것을 실험 신뢰성의 제1원칙으로 삼는다. 행동 수칙으로 바꾸면:

  • 놀라운 결과일수록 축하하기 전에 의심한다.
  • 의심의 순서를 미리 정해 둔다 (아래 체크리스트).
  • 효과 크기에 대한 사전 분포를 가진다. 지난 수백 번의 실험에서 +1%도 드물었다면, +10%가 진짜일 사전 확률은 아주 낮다.

3. 성공률, 그리고 왜 그것이 기저율인가

업계에서 반복 인용되는 수치 (정확한 값은 책에서 확인할 것):

  • Microsoft 전체: 약 1/3이 지표 개선, 1/3은 효과 없음, 1/3은 악화
  • Bing처럼 성숙한 제품: 개선은 약 10~20%

이 숫자가 주는 의미:

  1. 실험 없이 출시하면 1/3은 해를 끼친다. 실험이 선택이 아니라 필수인 이유.
  2. 성공률은 거짓 발견 비율을 결정하는 기저율이다. 아래 계산.
  3. 성숙한 제품일수록 성공률이 낮고, 따라서 "놀라운 승리"가 가짜일 확률이 높다. 재현(replication)을 요구하는 문화가 통계적으로 정당화된다.

거짓 발견 비율 계산 (손으로)

실험 100개, 진짜 효과 비율 1/3, 검정력 80%, α = 0.05.

진짜 효과 있음 (~33)효과 없음 (~67)
p < 0.0533 × 0.8 ≈ 27 (진양성)67 × 0.05 ≈ 3 (위양성)
p ≥ 0.05~6 (놓침)~64

유의한 결과 약 30개 중 진짜 27개, 가짜 3개. 유의한 결과의 약 90%가 진짜.

같은 계산을 기저율 1%로 하면 진양성 0.8, 위양성 5 → 유의한 결과 중 진짜는 15%. 거짓 발견 비율은 α가 아니라 기저율이 결정한다.

용어 구분: false positive rate는 효과 없는 것 중 유의하게 나온 비율(α). false discovery rate는 유의한 결과 중 가짜의 비율. 둘을 구분해서 쓴다.

4. 실험 성숙도: Crawl → Walk → Run → Fly

책의 4단계 모델. 축은 두 개:

  • 규모: 연간 실험 수. 대략 수십 → 수백 → 수천 → 수만
  • 플랫폼 자동화: 수동 분석 → 표준 지표와 자동 리포트 → 자동 가드레일·SRM 경보 → 셀프서비스로 누구나 실험

조직 범위나 다룰 수 있는 가설의 폭은 이 두 축의 결과로 나타난다. "우리 조직은 어느 단계인가"를 진단하는 질문이 나오면 이 틀로 답한다.

5. "너무 좋은 결과" 체크리스트

순서가 중요하다. 값싼 검사부터.

  1. SRM — 할당 비율이 설계와 맞는가 (06회)
  2. 가드레일 지표 — 지연시간, 오류율, 크래시처럼 "나빠지면 안 되는 것"이 멀쩡한가
  3. 세그먼트 일관성 — 효과가 브라우저·날짜·국가에 걸쳐 고르게 나오는가. 한 곳에서만 터지면 로깅 버그를 의심
  4. 로깅·계측 — 처치군에서 이벤트가 두 번 기록되지는 않는가. "너무 좋은 결과"의 가장 흔한 원인
  5. 이상치 — 몇 명의 극단값이 평균을 끌고 가는가. 매출 지표에서 특히
  6. 신기 효과 — 일별로 효과가 줄어드는가
  7. 트리거 분석 — 실제로 변화를 본 사용자만으로 계산하면 어떻게 되는가 (06회)
  8. 재현 — 설명이 안 되면 다시 돌린다

확인 문제

Q1. 어떤 팀이 실험 100개를 돌려 p < 0.05인 결과 20개를 얻었다. 성공률 1/3, 검정력 80%일 때 이 중 진짜는 대략 몇 개인가?
Q2. 같은 상황에서 검정력이 50%라면? 거짓 발견 비율은 어떻게 변하나?
Q3. "새 추천 알고리즘을 켠 사용자가 더 오래 머문다"는 분석이 왜 효과의 증거가 아닌가? 한 문장, 영어로.
Q4. 매출 +10%가 나왔는데 SRM도 없고 가드레일도 멀쩡하다. 다음에 볼 두 가지는?
정답
  1. 약 18개 (유의한 결과의 ~90%가 진짜).
  2. 진양성 33 × 0.5 ≈ 17, 위양성 3 → 유의한 결과 중 진짜 ~85%. 검정력이 낮아지면 거짓 발견 비율이 올라간다. 검정력은 놓침(2종 오류)만의 문제가 아니다.
  3. 예: Users who turned the feature on differ from those who didn't, so the comparison measures selection, not the feature's effect.
  4. 세그먼트 일관성(한 브라우저·날짜에만 몰려 있는가)과 로깅 중복(처치군에서 이벤트가 두 번 찍히는가).
